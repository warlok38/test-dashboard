# Производственный дашборд

> Описание нужно доработать

Внутреннее веб-приложение для просмотра сводных производственных показателей. Проект объединяет ключевые показатели, графики, карту активов,
фильтрацию по производственным периодам.

## Быстрый старт

### Требования

- Node.js 20.19.2 или выше;
- доступ к корпоративному API;
- Kerberos-токен для локальной разработки.

### Установка и запуск

После клонирования репозитория перейдите в каталог проекта и установите зависимости:

```powershell
npm ci
```

Создайте в корне проекта файл `.env.local`:

```dotenv
NEXT_PUBLIC_API_BASE_URL=
KERB_TOKEN=
RUN_MODE=development
```

Укажите в нём адрес корпоративного API и актуальный `KERB_TOKEN`, затем запустите
dev-сервер:

```powershell
npm run dev
```

Храните реальный Kerberos-токен только в `.env.local`. Файл исключён из Git и не должен
попадать в коммиты. Подробнее о сценариях авторизации см. в
[описании auth flow](docs/auth-flow.md).

## Архитектура

Проект использует мягкую адаптацию Feature-Sliced Design для Next.js App Router:

```text
src/
├── app/       # маршруты, layout, providers и композиция приложения
├── widgets/   # крупные самостоятельные блоки страниц
├── features/  # пользовательские действия и интерактивные сценарии
├── entities/  # доменные типы, данные и бизнес-вычисления
└── shared/    # переиспользуемая инфраструктура, UI, API и утилиты
```

Зависимости направлены сверху вниз:

```text
app → widgets → features → entities → shared
```

Слой может импортировать только нижележащие слои. Страницы в `src/app` остаются тонкими:
они обрабатывают параметры маршрута и собирают экран из модулей нижних слоёв.

## Правила разработки

- Сохраняйте страницы в `src/app` server-first. Клиентские компоненты используйте только
  для хуков, browser API, интерактивности и Ant Design там, где это необходимо.
- Импортируйте модули через их публичные `index.ts`; не обращайтесь к внутренним файлам
  другого slice напрямую.
- Не добавляйте старую структуру `src/components`. Размещайте код в `widgets`, `features`,
  `entities` или `shared` согласно его ответственности.
- Используйте Redux Toolkit для общего состояния приложения, а локальное UI-состояние
  оставляйте внутри компонентов.
- При работе с Ant Design ориентируйтесь на API v6 и не используйте deprecated props.
- Используйте дизайн-токены из `src/shared/styles/tokens` вместо одноразовых цветов,
  отступов и размеров.
- В CSS применяйте общие custom media queries, а в React — хук `useScreen`; не дублируйте
  значения breakpoint-ов в компонентах.
- Используйте `kebab-case` для каталогов модулей, `PascalCase` для React-компонентов и
  `camelCase` для хуков и вспомогательных функций.
